# CodeChess

> Scaffold generated by Codex (agent session) — hackathon kickoff pass.
> No git commands were run to produce this scaffold. Initialize the repo yourself when ready (`git init`, first commit) — that step is intentionally left to the team.

Multiplayer terminal chess for developers waiting on AI coding agents. While your agent (Codex, etc.) is heads-down working, CodeChess matches you with another waiting developer for a quick game — the game pauses the instant either agent finishes.

This is not a chess app. It's a test of an interaction model: **overlapping AI wait-time becomes lightweight synchronous multiplayer**.

## Repo layout


## Standalone UI

The terminal client can run before the server and agent tracks are available. From the repository root:

```bash
npm install
npm run ui:mock
```

See [`client/README.md`](client/README.md) for controls and WebSocket configuration.

## Definition of done

```
Two terminals → two AI prompts → both agents running → automatic matchmaking
→ interactive terminal chess → realtime moves → one agent completes
→ game pauses → AI answer appears → same game can resume later
```

If that sequence works reliably end-to-end, stop building. Everything past that line is polish (see PRD "Stretch Goals").

## Explicitly out of scope

Accounts, auth, Elo, ranked matchmaking, friends, chat, spectators, chess clocks, tournaments, multiple games per person, full DB architecture, a custom chess engine, direct terminal-to-terminal shell access, shared shell sessions, Claude/Gemini integrations, production-grade security. Do not build these during the hackathon — see PRD for rationale.
